02 · HOW IT WORKS

四步流水线Four-step flow

STEP 1读凭证Credentials~/.flomo_credentials（access_token + webhook），本地文件
STEP 2拉 memoFetchflomo API 游标分页，近 7 天，429 退避重试cursor pagination, 7-day window, 429 backoff
STEP 3匹配规则MatchTAG_RULES 自上而下，跳过已有层级标签top-down, skips existing branch tags
STEP 4写回Write编辑 memo 追加 #标签edit memo, append #tags
凭证边界：个人 access_token 只存在 ~/.flomo_credentials（JSON），永远不进仓库；脚本内硬编码的 sign 密钥是 flomo web 端的全局签名常量（逆向自其 web app），非个人凭证。API 属非官方接口，flomo 改版可能失效。 Credential boundary: your token lives only in ~/.flomo_credentials; the hardcoded sign key is flomo's app-wide web constant (reverse-engineered), not a personal secret. Unofficial API — may break on flomo updates.
03 · FAQ

常见问题 · 四问速览FAQ · The four questions

Q.1解决什么问题？What problem does it solve?＋
flomo 记得快但标签靠手补，积压一周就再也不想整理。脚本按你定好的三级体系每周自动补标，笔记库保持可检索。Quick capture dies without tags; after a week nobody back-fills. The script keeps the library searchable on your own taxonomy, weekly, hands-free.
Q.2什么场景用？得到什么结果？Scenario and outcome?＋
每周定时跑（cron/launchd 自排）：过去 7 天的 memo 自动带上 #交易/订单流 这类三级标签；同层不重复、已有标签不覆盖。Run weekly via cron/launchd: last week's memos get three-level tags — no duplicates, no overwriting.
Q.3内部是什么结构？How is it structured?＋
单文件 389 行：TAG_RULES（7 大类三级标签的关键词表）→ get_tags_for_memo（去重匹配）→ flomo API 客户端（游标分页 + MD5 sign 签名，逆向自 flomo web）→ 编辑写回。依赖仅 requests。One 389-line file: TAG_RULES → matcher → flomo API client (cursor pagination + MD5 sign) → write-back. Only requests.
Q.4能复用什么？What can you reuse?＋
① 「优先级即顺序」的规则表写法；② flomo 非官方 API 的签名与分页配方（sign = md5(sorted qs + secret)）；③ 「跳过已有父级标签」的去重逻辑；④ 凭证本地文件化的习惯。改成你自己的 TAG_RULES 即可用于任何 flomo 账号。Priority-ordered rule tables, the flomo signing/pagination recipe, parent-tag dedup, and local credential hygiene — swap in your own TAG_RULES and run.
